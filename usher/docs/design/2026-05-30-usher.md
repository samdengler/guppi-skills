# Usher — design

**Date:** 2026-05-30
**Status:** Initial scaffold
**Epic:** guppi-skills-txz

## Purpose

Given a **movie + theater + number of tickets + optional time window**, rank a chain's
showtimes by the user's **format preferences** and find the best **contiguous seats**
per the user's **saved seat preferences**. Booking stays **human-in-the-loop**: usher
prints the ranked options and a deep link to the seat page; the user logs in and pays.

Usher never enters payment details or finalizes a purchase.

## Reverse-engineering notes (regmovies.com — Regal)

Captured live on 2026-05-30 driving a real Chrome session.

- **Server-rendered (Next.js) behind Cloudflare** bot protection. Listing pages carry
  data in HTML, not a clean public XHR. A standalone HTTP client gets challenged — so
  data calls must run **inside the user's real browser session**. See the browser-bridge
  dependency below.
- **Theaters** are keyed by `theatreCode` (e.g. Regal Atlantic Station = `1346`).
- **Showtimes:** `…/movies/<slug>?selected=<theatreCode>` renders that theater's showtimes.
  Showtime buttons have DOM ids `show<theaterIdx>time<n>` (e.g. `show0time61`). The session
  id is **not** an attribute — clicking the button navigates to
  `…?id=<sessionId>&site=<theatreCode>&date=MM-DD-YYYY`.
- **Seat map (clean REST):** `GET /api/GetSeatPlan?theatreCode=<id>&sessionId=<id>` →
  JSON `SeatLayoutData.Areas[].Rows[].Seats[]`. Each seat:
  - `PhysicalName` — row letter (on the Row)
  - `Position.ColumnIndex` — grid column (use for centeredness)
  - `Id` — the seat number shown to the user (use to match saved picks; differs from
    ColumnIndex because aisles offset numbering)
  - `Status` — **0 = available, 1 = taken**; 3 & 7 = accessible/blocked (inferred)
- **Orientation:** row **A = front (nearest screen)**; lettering climbs to the back.
- The seat-map header shows the Regal **"Screen N"** label — the reliable auditorium anchor
  (the user's hand-numbering of auditoriums was approximate).

## Ranking rules (confirmed with user)

1. **Format first.** Regal → IMAX first, then large-format (RPX), then Standard/VIP.
   **Skip ScreenX.** Offer **4DX only for action movies.** AMC → Dolby first.
   Format preference outranks timing and seat quality.
2. **Contiguous seats only.** For N tickets, all seats must be one unbroken run in a
   single row, or it is not a valid option.
3. Within a row, "best" = closest to row center, where `center = (minColumnIndex +
   maxColumnIndex) / 2`.
4. If a saved pick for the specific screen is available, use it; otherwise fall back to
   the nearest available match, then to the general center/good-row heuristic.

## Architecture

CLI-first (per repo philosophy). Modules:

- `ranking.py` — pure Python, fully unit-tested. Format ranking, time filtering,
  contiguous-seat finding, center scoring, saved-pick matching. **No I/O.**
- `prefs.py` — load/save preferences as JSON under XDG data dir; seeded with the user's
  Regal/AMC preferences.
- `browser.py` — minimal AppleScript bridge to run JS in the active Chrome tab
  (`osascript`), so data calls run in the authenticated, Cloudflare-cleared session.
  **To be refactored onto the `surfer` skill** once `surfer run` is implemented
  (guppi-skills-j44).
- `regal.py` — Regal provider: build URLs, derive session ids, fetch `GetSeatPlan` via
  the browser bridge, parse `SeatLayoutData` into a flat seat list. `parse_seat_plan()`
  is pure and testable against a captured fixture.
- `cli.py` — Typer app: `find`, `showtimes`, `seats`, `prefs`, plus `skill` group.
